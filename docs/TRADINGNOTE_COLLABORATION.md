## 1. 证据边界与阶段

TradingNote 是以交易笔记和复盘为核心的个人投资应用：连接用户写下的理由、成交、持仓及行情，让复盘从“赚亏多少”进入“当时怎么想、是否按自己的计划执行”。项目采用 React/Vite、FastAPI 和 SQLite；产品交互以英文为目标，笔记引用保留原文。技术栈和早期数据接口可由 [旧后端提交](../../.qoder/evidence/git/d7ce8b4.patch) 与 [Today 初版提交](../../.qoder/evidence/git/876cbf7.patch) 核对；语言方向记录于 [Agent 会话](../../.qoder/projects/E-----------AI--/a8d26899-0f15-4dc9-9233-53a7064873a5.jsonl)。

| 阶段 | 任务与交付 | 本包的证据类型 |
|---|---|---|
| 10-17～10-21：旧管道与 Today AI | Daily Summary、Trade Review、交易账本与持仓状态逐步接通 | 同期设计与调试会话、完整 Git 补丁 |
| 10-23～10-25：Agent 引擎升级 | 方案、隔离开发、11 工具、证据引用、输出约束和评测 | 完整可见会话、任务、代码补丁、评测报告 |
| 10-24：宣发创意 | 30 秒《Again》创意方案；团队确认采纳方向 | 方案会话、提交人采纳陈述 |
| 日常修复 | 导入、图表、复盘、行情状态、构建等 18 个案例 | 对应会话、任务或完整 Git 补丁 |

**证据组织**：17 份项目会话均以相同 `user` / `assistant` JSONL 结构置于 `projects/E-----------AI--/`；正文按任务引用，不按工具分栏。每份原始日志的出处、行号与 SHA-256 保存在 [manifest](../../.qoder/evidence/manifest.json)，以免格式迁移造成来源误认。包内是完整的人类提问和助手可见回复；图片、带签名链接、本机路径、凭据及内部执行日志按[目录说明](../../.qoder/README.md)处理。

## 2. 旧管道版本：Today 页 AI 能力搭建

这是升级版 Agent 之前的项目管线，现可同时核对设计往返和代码实现：

1. **先把两种复盘分清楚（10-18）**。用户要求 Daily Summary 和 Trade Review 分别生成、分别保存。前者回答市场与组合当日结果，后者追踪交易笔数、记录完整度、历史理由与计划是否被遵照；复盘需要引用真实记录，而非问答式泛评。检查发现旧输入只有当天交易和笔记，无法可靠完成大盘归因或历史计划核对，因而补上下文组装与独立的数据契约。[设计对话](../../.qoder/projects/E-----------AI--/01a14f45-956b-7a31-ade2-82cdfe6b9e96.jsonl) · [Today 初版](../../.qoder/evidence/git/876cbf7.patch) · [Trade Review V2.1](../../.qoder/evidence/git/3a97012.patch)。
2. **行情事实先于解释（10-18）**。团队探测 Wind 行业/指数能力时，工具目录返回 402，无法把“额度不足”误判成“不支持”；评估 AkShare 后，又因行业接口稳定性与等待时间，把它退出日评关键路径。最终以结构化行情和交易账本计算数字，缺行情时降级，不让模型编行业或盈亏。Web Search 只作为有来源的背景解释备选，不承担计算。[取舍对话](../../.qoder/projects/E-----------AI--/01a14f45-956b-7a31-ade2-82cdfe6b9e96.jsonl) · [行情与组合提交](../../.qoder/evidence/git/958b0ff.patch)。
3. **按标的与日期形成可复用账本（10-19～10-20）**。导入的历史交易进入后端交易表，由组合引擎滚动计算成本、持仓和日盈亏；Overview、日历和复盘共用派生状态。用户追问是否必须新建“按标的存储”的底表时，核对发现现有账本已包含代码、市场、币种与交易日期，因此优先复用，不做无收益的迁表。多币种原币种分别展示，缺汇率时不直接合计。[导入与账本对话](../../.qoder/projects/E-----------AI--/01a15471-a794-78b3-a985-1b4b3d126448.jsonl) · [滚动组合](../../.qoder/evidence/git/958b0ff.patch) · [账本 Today](../../.qoder/evidence/git/ed04827.patch)。
4. **让 AI 叙述受事实约束（10-21）**。自由文本曾把已记录证券损益写得像完整账户日收益。团队先改成程序生成的三段事实卡；用户指出“日报仍应有 AI 输出”，于是恢复受约束的叙述层：程序计算指数、行业、盈亏和贡献，模型只写市场/组合/洞察，失败退回事实模板。统计范围按用户要求锁定已导入标的和交易，不凭缺失的资金流水推算全账户收益率。[口径修正与 AI 旁白对话](../../.qoder/projects/E-----------AI--/01a15c67-45a2-7a53-8212-429968025852.jsonl) · [英文日评提交](../../.qoder/evidence/git/c85e719.patch) · [当前相关差异](../../.qoder/evidence/git/working-tree-current.diff)。
5. **把场景与跨日缓存做成通用逻辑（10-21）**。Trade Review 按“交易/笔记”是否存在分为四种输出深度；无记录日给空态，不调用 AI，事后补写的理由不能被评为事前纪律。随后发现只重生成 6 月 22 日会让 23、24 日继续显示旧模板，根因是读取路径没有校验规则版本；加入按所选日期的缓存升级，同一天重复点击也重新读取。对话记录了从单日修补转向通用规则的纠错过程。[四模式与缓存对话](../../.qoder/projects/E-----------AI--/01a15c67-45a2-7a53-8212-429968025852.jsonl) · [当前相关差异](../../.qoder/evidence/git/working-tree-current.diff)。

**旧新边界**：Agent 引擎升级先切自由聊天；Today、Review Trades、Behavior Insights 保留独立管线，避免切换影响已有场景。[边界讨论](../../.qoder/projects/E-----------AI--/340d9fc3-bff9-44b1-b75d-f7375ea3fbac.jsonl) · [分流实现](../../.qoder/evidence/git/4e27193.patch)。

## 3. Agent 引擎升级：从方案到评测

**需求与选型。** 用户要求开放式聊天能跨交易、笔记、持仓、统计、行情与新闻回答，同时保留旧场景，避免大改原项目。方案讨论比较了 opencode、pi、dsh 与现有 Python/FastAPI 栈；MVP 选择在 FastAPI 内自建薄 harness：分层上下文、受限工具调用、状态、证据书与输出检查。先建立独立副本，再在 `agent` 分支提交。选择依据、隔离要求和分支过程分别见 [方案会话](../../.qoder/projects/E-----------AI--/a8d26899-0f15-4dc9-9233-53a7064873a5.jsonl)、[分支会话](../../.qoder/projects/E-----------AI--/340d9fc3-bff9-44b1-b75d-f7375ea3fbac.jsonl) 与 [实现提交](../../.qoder/evidence/git/4e27193.patch)。

**被团队纠正的核心设计。** 初版方案把笔记当作普通检索来源，用户指出产品最重要的是“当时怎么想”，于是定下“笔记是决策证据、成交是行为证据、行情/新闻是环境证据”。方案曾提出加笔记时间戳，随后用户指出理由可能事后补写，因此撤回“事前/事后”的机械区分；回答只能说“用户记录的理由”，不能宣称一定是事前承诺。对“卖飞”可作事后判断，但须同时核对是否符合用户记录的策略。这几轮明确的提出、反驳、修改都在 [同一会话](../../.qoder/projects/E-----------AI--/a8d26899-0f15-4dc9-9233-53a7064873a5.jsonl) 中，亦留在 [项目记忆](../../.qoder/projects/E-----------AI--/memory/agent-harness-plan.md)。

**实际实现。** `backend/app/agent/` 建立 context、state、runner、runtime、registry 等模块。模型最多进行 5 步工具调用；11 个工具涵盖交易档案、笔记、标的解析、成交、统计、行为事实、持仓、每日上下文、日线、指数和新闻。EvidenceBook 给工具证据编号 `[E#]`、笔记编号 `[N#]`，回答可回查来源；OutputGuard 审核无依据的动机、数字、引文、实时价格与投资建议等，失败时重写或降级。`AGENT_ENGINE` 默认 `legacy`，设为 `v2` 才切换自由聊天，旧场景暂留原管线。模块与开关逐文件见 [完整提交补丁](../../.qoder/evidence/git/4e27193.patch)；10-24～10-25 的英文化与路由改动见 [当前本地差异](../../.qoder/evidence/git/working-tree-current.diff)。将旧场景 skill 化只是后续讨论，不能写成已经迁入 v2。[迁移讨论](../../.qoder/projects/E-----------AI--/340d9fc3-bff9-44b1-b75d-f7375ea3fbac.jsonl)。

**评测结果按口径分开。** 10-24 的 30 条合成用例，脚本模式 v2 30/30 仅证明证据通路；真实模型自动规则 v2 14/30、legacy 4/30，人工复核未通过，问题包括动机过度解读、数字口径混淆和删句后表格残缺。[人工复核原报告](../../.qoder/evidence/evaluations/manual-recheck-review.json)。10-25 英文化至 35 条问题后，脚本模式 v2 35/35、legacy 22/35；英文真实模型自动规则 v2 15/35。英文 live 报告仍要求人工复核，不能宣称 P2 验收通过。[评测会话](../../.qoder/projects/E-----------AI--/7b279daf-a2bf-417c-a0cc-b77ba7183744.jsonl) · [35 例脚本报告](../../.qoder/evidence/evaluations/scripted-35-20261025.json) · [35 例 live 报告](../../.qoder/evidence/evaluations/live-35-20261025b.json)。

## 4. 宣发创意：《Again》方向被采纳

先在[产品定位对话](../../.qoder/projects/E-----------AI--/01a16181-b5cf-7ba2-854f-e10fa020e40e.jsonl)中把交易记忆与复盘定为核心卖点，回测列为后续能力，Feed 保持辅助权重；[视频分镜对话](../../.qoder/projects/E-----------AI--/01a161a4-12bf-7393-883d-17e51be281c4.jsonl)讨论了 Remotion、日历视觉参考与现有产品画面的使用。随后团队提出约 30 秒开场：深色背景、多年龄人声与气泡字幕逐渐加速，最终叠成节奏。关键修改是让人物讲**记录难坚持、只看盈亏、规则一再失守**等具体痛点，而不是反复说“复盘很重要”；前 3 条人声保持可听清，之后的“again”进入电子节拍，结尾由珊瑚色 The Mark 收束。方案复用既有 120 BPM 分镜与调研线索，并提出以身份标签/声波圈代替真人脸、注明配音演绎。[《Again》完整方案会话](../../.qoder/projects/E-----------AI--/d37cc574-34c0-4295-b2d7-a46c41c5b9d0.jsonl)。

**采纳依据与边界**：提交人本次明确该创意“被采纳”，已作为[提交人陈述](../../.qoder/evidence/submitter-statement.md)放入证据包。方案会话证明内容与推导；目前没有《Again》单独成片或上线记录，因此本文只写“创意方向被采纳”。
